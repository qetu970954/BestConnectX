# 網路與輸入表示研究

[English](network-research-2026.md) · [學習率](learning-rates.zh-TW.md)

檢查日期：2026-10-04。**保留殘差基準和全部八個輸入。** 池化價值和單一區塊注意力已實作成實驗，不是直接升級。想找指令，先看[模型選擇和本機檢查](model-options.zh-TW.md)；這頁說明點子背後的論文。

以下來源都沒證明能提高本專案五子棋或六子棋的每小時棋力。論文結果和本機檢查分開看；這份研究本身沒有新增訓練或效能量測。[架構決策](adr/0002-shared-board-model-experiments.zh-TW.md)記錄了最後選擇實作什麼。

## 本專案的基準及共用輸入

預設使用 64 通道、六個一般殘差區塊、空間策略頭；價值頭將兩個空間通道攤平，再送入含 64 個單元的 MLP。訓練使用 Python／PyTorch，C++ 推論以 LibTorch 明確建立對應的層。模型從零開始訓練。因此，任何架構變更都須同步修改學習端與推論端，並明確處理 checkpoint 相容性。見[網路](../engine/network.py)、[C++ 推論](../engine/inference.cpp)及[模型選擇](model-options.zh-TW.md)。

保留 [Python 特徵](../engine/game.py)及 [C++ 特徵](../engine/runtime.h)的共用輸入順序：

| 平面 | 意義 |
| --- | --- |
| 0 | 當前玩家的棋子 |
| 1 | 對手棋子 |
| 2 | 剩餘落子訊號：剩兩次落子時全為一，否則全為零 |
| 3 | 當前玩家是否為黑方 |
| 4 | 當前玩家立即獲勝的單格落子點 |
| 5 | 屬於當前玩家兩格獲勝組合的格子 |
| 6 | 對手立即獲勝的單格落子點 |
| 7 | 屬於對手兩格獲勝組合的格子 |

一子回合的五子棋不使用平面 2、5、7，但六子棋需要它們。雙格遮罩只記錄格子是否參與組合，沒有記錄配對格子的身分。六子棋的一次落子後，下一子可能仍由同一玩家下，因此己方／對手的解讀不變；只有玩家真正切換時，價值正負號才切換。標籤及回傳值都必須保留此規則；[Python 回傳](../engine/search.py)及 [C++ 回傳](../engine/runtime.cpp)已依玩家身分處理。

若之後測試新的輸入表示，各方向的連線數量與空缺可在保留既有平面的前提下加入資訊。應依設定的連線長度及一／兩子棋規計算，不固定使用連五模式。這是待驗證假設：新增特徵會增加準備時間，也需要原生／參考實作一致性檢查。每個獨立 run 已知其棋規；這些遊戲不需要落子歷史來補足隱藏的棋規狀態。增加平面會改變第一層，須使用新模型／run，不能直接相容於既有 checkpoint。

## 已查核的第一手證據

**Rapfi，2025：直接相關的五子棋證據。** MixNet 學習各方向長度 11 格的模式，匯出為 codebook，再增量更新受影響的特徵。策略使用全域摘要，價值結合全域及區域摘要。論文在限制 CPU 的五子棋實驗中得到強棋力，尤其搭配 alpha-beta 搜尋時。不過，訓練使用約 3,080 萬個 Katagomo 局面與教師模型蒸餾，匯出模型約為 51–111 MiB。這些證據同時涉及表示、資料、推論及搜尋，沒有證明它能低成本取代本專案的 GPU 批次殘差學習端。[Rapfi 論文](https://arxiv.org/html/2503.13178)。[官方引擎 repo](https://github.com/dhbloo/rapfi)確認其五子棋／連珠及 alpha-beta／NNUE 實作背景。全域摘要值得改寫測試；重製整套引擎則是大得多的工作。

**ResTNet，IJCAI 2025：圍棋及 Hex 的卷積／注意力混合證據。** 它保留每格一個 token，交錯使用殘差與帶相對位置的 Transformer 區塊。在論文的 9×9 圍棋比較中，RRTRRT 對選定 KataGo 對手取得 60.80%，六個殘差區塊則為 54.60%；報告的推論時間由 3.067 增至 4.566 ms。每種架構的訓練約使用 200 GTX 1080 Ti GPU 小時。該比較中的純注意力模型較弱；增加注意力沒有一致改善。這些是作者的對手比較及硬體量測，不是本引擎的量測。未評估五子棋或六子棋。[IJCAI 論文](https://www.ijcai.org/proceedings/2025/0828.pdf)、[官方程式碼及實驗設定](https://github.com/rlglab/restnet)。

**KataGo，已查核的 2026 實作。** 架構文件描述卷積全域池化區塊、池化策略／價值路徑，以及使用可學習二維旋轉位置、RMSNorm、SwiGLU 的巢狀瓶頸 Transformer。文件列出 2026-08-25 進入主要訓練 run 的 Transformer 模型，約有 1,050 萬至 7,040 萬參數。其 Elo 表使用相同 visits，且明確不包含推論速度；相對成本估計也會依後端、硬體及批次大小改變。[NetworkArchitectures.md](https://github.com/lightvector/KataGo/blob/master/docs/NetworkArchitectures.md)。[v1.17.0 發布說明](https://github.com/lightvector/KataGo/releases/tag/v1.17.0)記錄 C++ Transformer 支援及新的匯出／後端需求；[v1.18.2](https://github.com/lightvector/KataGo/releases/tag/v1.18.2)加入特定舊 NVIDIA GPU 的注意力加速。這是有大量推論工程支撐的圍棋證據，不能當作六子棋架構排名。

**六子棋研究的重點不同。** 一篇 2024 研究以約 1,300 萬局面比較一般及殘差 CNN 的 sudden-death 預測。可取得的摘要及章節節錄支持殘差 CNN 在此監督式任務上的用途。此次未取得完整實驗細節，因此不能用來判定策略／價值自我對弈的最佳模型。[Deep learning approaches to the game of Connect6](https://doi.org/10.1016/j.entcom.2024.100707)。JSAI 2021 的 AlphaZero／JL-UCT 開局庫研究，在 100 盤黑白平衡的對戰中，對沒有開局庫的同版程式取得 65%，和局計半勝。這證明開局／搜尋的貢獻，不是較新網路主體的效果。[JSAI 論文](https://www.jstage.jst.go.jp/article/pjsai/JSAI2021/0/JSAI2021_4N4IS1c05/_pdf/-char/ja)。

## 實際實驗順序

以下是適用於兩種棋規的假設，不是本專案已取得的改善：

1. **先測池化價值頭。** 保留八平面、64／6 主體、空間策略及單一價值目標。以小型 1×1 價值投影、全域平均池化及 64 單元 MLP 比較既有基準。它可移除輸入大小隨棋盤面積增加的全連接層，但價值頭會少了直接的空間細節；若損害戰術判斷，再考慮區域池化。全域摘要可能有助於評估分散的威脅，包括六子棋雙格威脅。
2. **接著測已實作的注意力變體。** 保留池化價值頭，再加入一個棋盤注意力區塊。完整注意力的格子配對工作隨格子數平方增加，也需要額外記憶體。更改預設前，先與 `residual` 及 `pooled` 比較。
3. **之後才考慮其他變更。** 64／8 主體、SE 式區塊、區域池化或方向性輸入，都是獨立假設，不是已實作的改善。Rapfi 式 codebook 還需要匯出、增量狀態及各棋規調整。只有實測棋力增益足以抵銷成本時，才一次加入一個變更。

晉升前，以相同權重及 normalization buffers，比對 Python／C++ 的策略與價值，包含黑白雙方、五子棋局面及六子棋的兩個落子階段。檢查全部八個平面、立即與雙格獲勝／防守、價值正負號、真實權重更新及停止／續訓。比較單局與搜尋批次延遲、學習吞吐量及記憶體峰值。各棋規分開進行交換黑白的成對對戰，使用相同開局與落子時限；報告不確定性，以及相同總訓練時數後的棋力，時數包含自我對弈與學習。固定局面 loss 或較快推論，都不足以證明棋力較強。繼續從零建立本機模型，不匯入已訓練 bot 權重。
