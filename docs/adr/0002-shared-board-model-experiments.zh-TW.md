# 五子棋與六子棋共用模型實驗

[English](0002-shared-board-model-experiments.md) · [研究](../network-research-2026.zh-TW.md) · [現行引擎](../native-engine.zh-TW.md)

2026-10-04，使用者要求將較新的棋盤網路概念實際用於五子棋及六子棋，並授權自行決定實作細節。我們保留既有殘差模型為預設，加入兩種可選實驗：池化價值頭，以及使用同樣價值頭、再加一個棋盤注意力區塊的模型。以小型模型測試全域資訊，同時保留 C++ 對弈／推論、Python 學習及全部共用回合特徵。

## 設計討論的決策

```text
在既有引擎測試較新模型 [使用者要求]
├── 同時支援五子棋及六子棋 [使用者要求]
│   ├── 保留全部八個輸入平面 [已確認約束]
│   └── 只有玩家切換時改變價值正負號 [棋規要求]
├── 比較而非取代預設 [實作選擇]
│   ├── residual：既有 64 通道／6 區塊基準
│   ├── pooled：相同主體及策略，價值頭改用池化
│   └── attention：pooled 再加一個注意力區塊
├── 保留原生推論及 Python 學習 [既有共識]
│   ├── 層、權重及 normalization buffers 一致
│   └── 保留原本的原生模型建立入口
└── 安全續訓已保存的實驗 [使用者要求]
    ├── 架構與權重、optimizer 一起保存
    ├── 新架構須使用新 run 目錄
    └── 恢復已保存學習率，本次不加排程
```

原移植 Q1–Q21 共識保留於[移植需求](../migration-requirements.zh-TW.md)。以下的具體層寬及位置，是要求範圍內的工程選擇，不寫成使用者另行逐項批准。持久訓練與長時間棋力比較仍由使用者啟動。

## 設計與其他選擇

池化價值路徑以 1×1 卷積投影至 16 通道，經 ReLU、各通道全盤平均池化，再送入 64 單元隱藏層及單一 tanh 輸出。注意力版本在殘差主體之後加一個 pre-normalized Transformer 區塊：四個 heads、可學習的二維相對位置 bias、兩倍通道寬的 GELU feedforward 路徑，不使用 dropout。使用 PyTorch／LibTorch scaled-dot-product attention。策略仍是每格一個分數；注意力通道數須為四的倍數。

兩種獨立變體可先比較池化價值頭，再加入注意力。池化會失去絕對布局；相對位置注意力增加全盤互動，也增加運算及記憶體。這些是提升棋力的假設，不是重製 ResTNet 或 KataGo，也不是已證實能改善低價值 loss 的方法。較大注意力堆疊、Rapfi codebook／匯出／增量狀態、匯入 bot 權重、新輸入平面及更換 optimizer 都延後，以免其成本混淆第一次比較。

## 影響與檢查

八平面順序及一／兩子回合棋規保持共用。六子棋第一子之後可能仍由相同玩家落子，標籤及搜尋回傳保留該玩家的價值正負號。雙格威脅平面保留，即使一子回合的五子棋不使用。各 run 的棋規及棋力結果仍分開處理。

架構寫入模型／checkpoint config；缺少此欄位代表既有 residual 模型。明確要求續訓時更改架構會被拒絕。原 C 介面 `model_create(size, channels, blocks, device)` 保留，實驗模型使用 `model_create_variant`。在原符號更改參數，曾對已載入的舊 DLL 重現空指標存取違規；分開入口避免此問題。修改原生來源後仍須依來源 hash 重新建置。未完 gate 保留既有程式碼 hash 檢查；修改來源後，須依文件使用 `--restart-gate` 封存及重新開始該比較。

交付前，檢查真實更新前後的 CPU 學習端／原生輸出一致性、黑白雙方及六子棋各落子階段、非零相對位置權重、完整 bot 回合、保存／凍結模型、續訓及既有預設行為。模型延遲與棋力分開量測。成為預設前，各棋規須分別進行交換黑白的對戰，以及相同總訓練時數後的棋力比較；功能檢查不足以決定。見[測試](../../tests/test_model_variants.py)及[量測指令](../../experiments/benchmark_native.py)。
