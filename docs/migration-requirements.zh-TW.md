## 已核准交付範圍

- **原生對弈：** C++ 負責棋規、棋盤生成、合法落子、特徵、PUCT、戰術、TSS 搜尋、獨立證明檢查、完整自我對弈、評估對弈及人機對戰。Python 遊戲參考實作僅供測試使用。
- **模型及學習：** C++ 執行模型推論。Python／PyTorch 定義及更新可設定的一般殘差網路。權重在安全點同步至原生推論模型，測試須比對兩端輸出。
- **續訓及儲存：** Checkpoint 保存有界 replay 樣本、未完成工作、模型及 optimizer 狀態。保留原子保存、磁碟上限、不可變模型快照及安全復原。不建立已完成自我對弈棋譜封存或永久逐局 replay 檔案。
- **Dashboard：** 將既有本機 dashboard 接入原生路徑，保留實驗狀態、學習／評估結果、近期棋局摘要統計及可玩的 bot 對戰。顯示真實資料、清楚錯誤及可用控制。不新增瀏覽器訓練控制、雲端服務或已保存自我對弈棋譜的重播檢視。
- **簡單設定：** 為分階段遊戲及模型大小提供 TOML presets，預設為 15×15 自由五子棋。兩份 cheatsheet 都須說明建置、preset 選擇、設定覆寫、自我對弈請求、訓練、續訓、dashboard 使用及檢查。指令須確認後才列入文件。
- **檢查及報告：** 依下列階段執行。已量測的 CPU 搜尋、C++ 推論、學習及檔案 I/O 時間分開報告，並列出效能量測所用棋規、模型、批次大小及工作執行緒數。不得將舊量測或參數數量當作新的效能結果。

Dashboard 及框架須實際實作，不是只修改文件。不能僅憑短測試承諾棋力提升。

## 已同意驗證階段

1. **3×3**：先完成一盤，再比對合法局面／minimax 參考，並檢查 C++ 推論、學習及續訓。
2. **15×15 自由五子棋**：比對原生／參考棋規及戰術案例，檢查權重更新、續訓、完整棋局、時間及 GPU 記憶體。
3. **19×19 六子棋**：前兩階段檢查通過才進入。加驗未滿回合、兩子防守、提早獲勝、證明檢查與續訓。

CPU 檢查不計入 GPU 預算。GPU 測試程序從啟動到結束的實際時間全部計入，包含啟動及暖機。超出上限前停止或先詢問。

## 必須保留的檢查

不能移除合法落子檢查、真實終局結果、戰術必勝聲明的獨立檢查、安全保存、磁碟上限或既有檔案保護。

撤回實驗重現目標，不代表撤回上述安全檢查。
