One engine, two ways to use it

Train from the command line. Inspect results and play in the browser. Gomoku and Connect6 share the same configurable engine, but use separate weights and data.

Arrows show calls and data use, not concurrent stages or disk-write order. Shared dependencies of bot play and comparison are stated in their boxes rather than repeated as crossing lines.

How the pieces fit

  1. Choose rules and a run directory. The same engine supports square sizes 2–25, one- or two-stone turns, and configurable winning lines.
  2. Generate real terminal games. Verified threat-space search (TSS) guides moves; bootstrap uses a heuristic, then unresolved positions use policy/value tree search (PUCT). Unknown proofs never award wins.
  3. Learn from recent replay. The learner uses 20,000 recent positions and randomly sampled rotations/reflections. Search, learning, saves and evaluation run in sequence. There is no separate actor pool or shared inference service.
  4. Save and compare. Snapshots occur every 1,000 completed games. The first is a baseline; later candidates need more than 50/100 points and valid histories/timing to replace the best. Evaluation receives about 20% of active time and never enters replay.
  5. Inspect or play. The browser reads loss, comparison results and the latest 1,000 saved self-play games. It has no training controls. Bot requests are rejected while CLI training/evaluation owns the run lock.

Original C++ kernels accelerate CPU features and PUCT selection; trees and proof verification remain Python. Raw game records stay saved; dashboard and learner windows do not prune them.
